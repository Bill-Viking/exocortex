# Exocortex on Codex

This file adds surface mechanics to the law book: the two law files your AGENTS.md names — the engine's laws and the owner's own. Read both in full. Follow current user instructions and actual app permissions; this file does not grant extra access.

`{{HUB}}` is the installed hub. `{{SYNC}}` is its configured sync command including the interpreter. The installer renders both before use. Run hub commands from the hub, using `python3` or `python` on Windows. Other command arguments describe values to read from the record.

## Wake

1. Read the real clock and installed machine record. Verify the actual project folder; in a repository inspect its root, branch, HEAD and working state.
2. Check required carriers and run `{{SYNC}} pull`. Report a denied or failed operation accurately; do not call the brain current from a failed command.
3. Choose the arc from the work, not the folder. Check `python3 tools/who-is-live.py --pen --arc <arc> --title "<title>"`, stamp with `python3 tools/i-am.py <mind> <effort> "<title>"`, claim a free arc with `python3 tools/claim.py --claim <arc> "<title>"`, and repeat the pen check.
4. Read the project's full STATUS, registered memory index, relevant notes and matching opener. A held claim makes this session a reader, regardless of vendor.
5. Run `python3 tools/mail.py --read <address> --title "<title>"`. Use a supported background waiter when it can wake this surface; otherwise read again at each turn start and before close.
6. Run `python3 tools/personal.py --wake --by <mind>` and follow the law book's first-run conversation: say its `say:` and `ask:` lines in those words, then pass the owner's reply back unchanged.

The registered mind or persona supplies the plate name. State the actual model and effort only when observed or supplied by the owner. Use native title tools when present; otherwise give the exact title and say it has not been applied.

## Access and instructions

Codex can load global and project `AGENTS.md` instructions. Keep the installed routing text short and point it at the shared law and this addendum rather than maintaining a second law book. See the [official instruction-discovery guide](https://developers.openai.com/codex/guides/agents-md/).

Inspect the active surface's filesystem, network and approval limits. Do not assume every Codex installation shares the same sandbox. On a denial, use the supported permission path or the installed, authorized sync service. Report its actual receipt; do not bypass a restriction or change security settings merely to silence an error.

If the surface cannot access local files or tools, say what is unavailable. Use supplied state and provide clearly labelled STATUS, opener, mail or memory deltas for an authorized file-capable session. Do not claim to have acquired a writer claim, inspected a branch, changed a title or synced files without evidence.

## Work and memory

Use the same registered project notebook as other vendors. Follow the starter law's one-fact note shape and index rule. Resolve aliases from the installed memory mapping; do not create a separate notebook because a guessed path is absent.

Write only within the task, claim and available permissions. Preserve unrelated edits. Keep credentials, raw transcripts and vendor-private caches local. A cloud session is outside the local brain unless its authorized environment can actually read and carry the shared record.

## Close

Read mail, update the owned STATUS and opener, save review findings on disk when relevant, and verify the work through its permitted carrier. Keep private hub state out of public program commits.

Retitle `ARCH` only after carryover is saved. Release each owned arc with `python3 tools/claim.py --release <arc> "<title>"`, then switch off only this session with `python3 tools/i-am.py --off <mind> "<title>"`. Push with `{{SYNC}} push` last and verify the files arrived in the brain.

If the push fails, follow the law book's failed-close recovery before continuing repair. State any remaining blocker and the next move. Do not automatically archive the just-retired session. The shared close ritual and one-day visibility default apply here too.
